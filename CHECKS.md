## Браузер

- BRUTAL: перевірено широкий екран, відкриття форми, вибір дати/часу, успішний демозапис і зникнення зайнятого часу. WordPress-сторінка також відкрита.
- Stockroom: додавання через форму, пошук артикула, збереження після перезавантаження, архівування та повернення останньої дії. Імпорт CSV через вибір файлу: один товар додано; експорт завантажив CSV.
- Мобільні версії перевірено в тестових iframe шириною 360 px (345 px доступного вмісту зі скролбаром): ширина документа дорівнює видимій ширині в обох проєктах. У Stockroom таблиця має власну горизонтальну прокрутку. Меню BRUTAL відкривається і закривається після переходу.
- Портфоліо: реальні скриншоти обох проєктів, модальне пояснення реалізації та правильна локальна адреса демо.
- Скриншоти збережені в `docs/assets/`; додаткові QA-знімки та резервна копія теми — локально в `build/` (не публікується).

## Межі

Статичні демо зберігають дані в браузері, WordPress — у MySQL. SMS, email, Telegram-сповіщення, платежі, повний журнал руху товарів і кілька майстрів не реалізовані. Це авторські демопроєкти, не перевірений сервіс для реального бізнесу. Одночасна подвійна заявка захищена унікальним індексом; окремий багатопотоковий навантажувальний тест не виконувався. Встановлений Chrome був згорнутий, тому адмінпанель Stockroom у його поточній сесії візуально не перевірено; серверний API перевірено під адміністратором через WordPress CLI.

У Local CLI бракувало необов’язкового розширення Imagick. Для перевірок використано локальну копію php.ini без цього розширення; системний конфіг не змінювався. На функції проєктів це не вплинуло.
